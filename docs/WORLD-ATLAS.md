# 世界地图使用与后续规划

## v1.3.0 一键生成

已加入 Azgaar 本地生成，可直接创建底图并导入城镇地点。操作和边界见 [一键地图生成](MAP-GENERATION.md)。

## v1.2.0 已接通的流程

在“世界”页面打开世界地图，创建地图后可以导入 PNG、JPEG 或 WebP 图片。支持 Azgaar 导出的 PNG 和自绘地图。图片最长边自动缩至 2048 像素，每部作品最多四张地图。

架空地图的坐标原点是图片左上角，X 向右、Y 向下。真实地理地图分别保存经度和纬度，底图须使用等经纬度投影，并填写西、东、南、北边界。可先创建坐标网格，再添加地点。

点击“在图上选点”后点选地图，或在地点编辑器中手动填写坐标。两个坐标均留空时，地点保存为“待定位”。地点有名称、别名、类别和说明。

选择地点后可以新增世界事件，或绑定已有事件。详情中显示故事日期、相关人物、事件经过、当地影响和关联章节，点击“打开正文”跳转到章节。写作页的“本章地点”列出事件已关联的地点，以及正文逐字提到的已建档地名和别名，点击后定位地图。

日期滑块显示截至所选日期的事件，并可结合章节、人物筛选。年份和月份精度的事件到该年或该月末计入，未定日期事件可单独选择包含。地点、事件和历史遗迹三类标记可以分别开关。

“AI 整理本章剧情”增加地名和数字日期字段。地名、日期须逐字出现在送审片段中，日期还要通过有效性检查。候选先进入审核列表，采纳时才创建正式事件。仅当名称或别名在当前作品中唯一匹配时绑定地点，重名与未知地点保留文字地点，列入待关联事件。地点已有坐标后，相关事件随即可以在地图上显示。

全库 JSON 备份包含地图图片、地点和事件关联。更换架空地图图片时按比例保留标记位置。删除地点或地图后，事件、人物、章节正文继续保留，事件的文字地点也保留，便于重新绑定。

## 当前边界

- Azgaar 原生 .map、SVG 矢量区域和图层结构尚未导入，目前采用导出的地图图片。
- 真实地理模式支持经纬度标记和自行导入的等经纬度底图。在线瓦片、自动地理编码尚未接入。
- 历史遗迹目前是地点分类标记。地点建立、毁灭和更名的年代演变尚未实现。
- 人物面板展示事件参与记录，人物实际行进路线、同行与离开时间尚待建立独立数据结构。
- 势力边界、多边形区域绘制、路线规划、六图层完整组合和自动世界模拟属于下一阶段。
- 日期提取目前接受原文中的数字年份或 ISO 数字日期。中文纪年换算和“次日”等相对时间需要作者补录。
- Android 真机、地图大图内存压力、真实模型提取质量和真实设备存储仍待验收。

## 下一阶段

1. 记录人物出发、经过和抵达节点，连成按时间过滤的路线，并保留章节及原文证据。
2. 建立势力档案与区域多边形，按生效日期记录控制权变化。
3. 增加道路与旅行路线编辑、地图区域选择，以及地图和章节片段之间更精确的定位。
4. 扩展日期解析与地理候选审核，再进行 Android 实机、性能和存储验收。

## 参考与依赖

地图采用本地打包的 Leaflet 1.9.4，许可证位于 web/vendor/leaflet/LICENSE。架空地图使用其非地理坐标系统，真实地理地图使用经纬度投影。[Leaflet 非地理地图说明](https://leafletjs.com/examples/crs-simple/)

VVD 的地图文档说明了导入地图图片并添加世界观内容的流程，本阶段采用相同的交互方向。[VVD Maps](https://vvd.crisp.help/en/article/maps-akxl85/)

StoryMap 提供人物与时空记录联动的参考。本阶段将同样的数据关联用于小说事件，并保留作者审核。[StoryMap](https://storymap.cn/index.html)

B 站视频页面直接读取受限，未将视频里的具体画面作为已验收功能依据。
